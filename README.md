# Communications Authority of Kenya — Website (concept: Media Harbour)

A static rebuild of the CA website in semantic HTML, modern CSS and vanilla ES modules, with no frameworks. The homepage is hand-written; the inner pages (About CA and Consumer Protection so far) are generated by a small standard-library Python script, and the generated HTML is committed, so the site still runs from any static server without a build step.
The layout and interactions follow the Media Harbour concept, while brand colours, logo and fonts (Inter + Maitree 700) come strictly from the current CA theme.

Version 2 applied a UX review (see `docs/ux-review.md`): a task-first section order, less motion, higher text contrast and an in-page cookie banner. Version 3 (client feedback) moved search and popular tasks into their own panel, slimmed the news with character limits, and added real partner logos and CA project photos. Version 4 turns the hero into an auto-playing slider with a consistent two-line headline rhythm, compacts the find panel into a single strip, and rebuilds News as a lead story plus a list.

## Run locally

Any static server works (ES modules need `http://`, not `file://`):

```sh
npx http-server -c-1 .     # then open http://localhost:8080/
```

Add `?placeholders` to the URL to outline every placeholder that still needs real content (see `docs/content-todo.md`).

After editing `index.html` (header, menus, footer) or anything in `src/`, rebuild the inner pages:

```sh
python3 tools/build.py                       # writes /<slug>/index.html, /people/<slug>/, /careers/<slug>/
python3 tools/build.py --preview OUT_DIR     # also writes a flat copy with relative links, for previews
```

Naming is BEM with a `ca-` prefix. Each section is self-contained markup (`<section class="ca-panel …">`) so it can be lifted into a WordPress template part.

## Inner pages

Every inner page shares one frame: the homepage header and menus (with the current page marked `aria-current="page"` and its section underlined in the main menu), a page hero on the brand's light-curve panel with a breadcrumb, the page title and a one-line summary, then the content, and the homepage footer.

| Layout | Used for | What it adds |
|---|---|---|
| `page` (default) | Most pages | Section navigation beside the content (sticky on wide screens, an "In this section" disclosure on phones) built from the main menu, so both always match |
| `landing` | Section overviews (About the Authority, Our Role in Your Protection) | Full-width panels instead of the side navigation; ends with the section's pages as link cards grouped as in the menu |

Content blocks, all in `pages.css`: prose, image beside text, document lists (type, size and a download icon, Kiswahili titles marked `lang="sw"`), people grid, profile, link cards, feature cards, icon list, numbered list, steps (vertical, or in a row on landing pages), FAQs (native `<details>`), callouts, office cards, vacancies, Director General's message, forms and the IMEI helper.

Shortcodes in `src/pages/*.html`, expanded by `tools/build.py`:

| Shortcode | Renders |
|---|---|
| `<!--docs:LIST-->` (add `cols=2` for two columns) | A document list from `src/data/documents.json` |
| `<!--people:GROUP-->` | The people in a group, in the WordPress order; names with a biography link to their profile |
| `<!--subpages:SECTION-->` | Every page in the section as grouped link cards |
| `<!--related:pages /a/,/b/-->` | Link cards for pages anywhere in the main menu (the build stops if a path is not in the menu) |
| `<!--jobs:all-->` | Vacancies with Open/Closed status and deadline |
| `<!--video:ID title="…" label="…" duration="m:ss"-->` | A link that plays the video in the same in-page player as the homepage |

## Porting to WordPress

- Asset paths are relative (`assets/...`). In a theme, prefix them with `get_template_directory_uri()`.
- Internal links are root-relative (`/tenders/`) and the search form is `GET /?s=`, so both work as-is.
- The main menu is rendered once. Each section is a `.ca-nav__item` holding an intro (title, one-line summary, overview link), groups of links (icon, name and a one-line description) and, where a section has a long tail, a quick-links band of plain links. The mobile menu is cloned from the same markup at runtime and drops the summaries, icons and descriptions.
- Videos: the row shows the channel's four latest videos (CA Kenya, channel ID `UCxg8WbhFIxqBqnWT9BaUDhQ`). In WordPress, fill it from the channel's public feed (`https://www.youtube.com/feeds/videos.xml?channel_id=UCxg8WbhFIxqBqnWT9BaUDhQ`) or the YouTube Data API on a schedule, cache the result, and copy each thumbnail into the media library so the page makes no requests to YouTube until someone presses play. Each card is a plain link to the video on YouTube; `videos.js` turns it into the in-page player.
- In WordPress, a custom `Walker_Nav_Menu` can output this markup: use the menu item's built-in **Description** field for the one-liner and a CSS class (e.g. `icon-licence`) or a custom field for the sprite icon name; top-level items carry the section intro, and second-level items marked as groups become headings.
- Inner pages: each generated page maps to one WordPress page with the same slug. Images and documents already link to the files uploaded to the WordPress site (`https://ca.programmer.co.ke/wp-content/uploads/…`), so nothing needs re-uploading; change `SITE` in `tools/build.py` if the domain changes before launch.
- Forms keep the WordPress field names (`cak_data[…]`, `cak_file_evidence`) and post to `/wp-admin/admin-post.php`. In the theme, add the hidden `action`, `cak_form`, nonce and anti-spam fields where the comment marks them and remove `data-form-preview` (that attribute makes this static build show a notice instead of sending).
- People cards link to `/people/<slug>/`, the WordPress profile URLs; only people with a biography get a link. Vacancy cards link to `/careers/<slug>/`.
- Character limits: news titles 80 (featured 100), summaries 140. In WordPress, enforce them server-side (e.g. `wp_html_excerpt()` / a word-boundary `mb_substr()`) and keep the full title in a visually hidden span, as `truncate.js` does.

## Behaviour without JavaScript

All content is visible: footer sub-lists expanded, every project tile shown (filter chips hidden), ticker as a scrollable row, and desktop menu sections open on hover or keyboard focus (each with its own white background). The hero search works (plain `GET /?s=`). Burger, header search, FAB, cookie banner and the pause buttons are hidden.

## Hero sizing

The hero is sized to the screen so the next section ("What do you need to do?" and its search box) always shows below it:

| Screen | Hero height | Notes |
|---|---|---|
| Phones (< 768px wide) | Its content plus a strip of photo, at most half the screen (`min(50svh, 420px)`) | Smaller type and button; the scrim follows the text block, so text stays ≥ 10:1 on every slide while the strip above stays clear photo |
| Phones on their side (≥ 568px wide, ≤ 540px tall) | Content only | The slide controls sit beside the slides on a navy backing; previous/next arrows are dropped (slide buttons and swipe remain) |
| Tablets and laptops | `clamp(440px, 62svh, 640px)` | Less padding on laptop-height screens (≤ 820px tall, e.g. 1366×768); on 768–1099px the side scrim stays deep further right because the text runs further across |

Measured with the header: the hero ends at 55–69% of the screen on common phones (390×844: 60%, 375×667: 66%), 83% on a 320×568 phone (was 86–107%), and 70–77% on tablets and laptops.

## Using CA orange

Orange is used sparingly and **only on light backdrops** (white, light blue). On navy and blue panels the accent is cyan or white. Two tokens, chosen by contrast (see `tokens.css`):

| Token | Value | Use for |
|---|---|---|
| `--action` | `--ca-secondary-600` `#BD4400` | "File a complaint" buttons on white surfaces (header, menu, help card: white text 5.3:1), the help button's icon, news dates, the news "Read more" cues and FAQ numbers (text 5.3:1 on white), small icons in Popular tasks and the contact list, text selection |
| `--signature` | `--ca-secondary-500` `#EC5B13` | Decorative details on light surfaces only: the bar before eyebrows on light panels, the header's scroll-progress line, the top edge of the mega menu and the menu overlay, logo-tile hover borders, link hover underlines, and the small welcome dot in the hero (CA's signature mark) |

Never: orange text on white in `#EC5B13` (3.5:1); orange on the primary blue (2.2:1); orange elements on navy panels (use cyan `--accent` or white).

## Motion

All motion lives in `assets/css/motion.css` and `assets/js/motion.js` (plus the slider in `carousel.js`). It uses transform, opacity and clip-path only; hover effects apply only on pointer devices; `prefers-reduced-motion` reduces everything to instant state changes and turns off the JavaScript effects.

| Where | What |
|---|---|
| Hero | Welcome line, title, highlighted second line, text and button rise in sequence on load and on every slide change; the photo slowly settles from a 1.08 zoom (paused with the slider); gentle scroll parallax |
| Header | Thin orange line shows how far down the page you are |
| Sections | Softer, longer scroll reveals; About text slides in from the left and USF text from the right; photos open like a curtain; eyebrow bars draw in; icon badges pop in after their cards |
| Cards and tiles | A soft light follows the pointer over service cards, stay-safe cards and project tiles; icon badges tilt and grow; project photos zoom while titles lift |
| Buttons and links | Lift on hover, a light sweep across filled buttons, press-down on click; news titles underline from left to right and the "Read more" arrow nudges forward |
| Main menu | One white surface opens under the header and resizes smoothly between sections; each section's content slides in from the side you came from and is clipped to the surface while it resizes; a soft pill glides behind the section under the pointer (or keyboard focus); groups fade up in sequence; link icons fill blue and tilt on hover |
| Other menus | Menu overlay, search and help items stagger in |
| Search | The placeholder cycles through example searches (IMEI, type approval, licence fees…) until you focus it |
| Filter | Project tiles return one after another |
| Help button | Pulses twice, once, 2.5s after load |
| Videos | Stills zoom gently and the play button fills blue on hover; the player dialog rises in over a blurred backdrop |

## Accessibility notes

- Skip link, labelled landmarks, exactly one H1, no skipped heading levels.
- Every overlay (menu, search, FAB) moves focus in, closes on Esc and returns focus to its opener; the menu traps Tab. The cookie banner sits in the page flow, so it never covers content or focus.
- Only the hero slider and the ticker move; both have a visible pause control, stop on hover/focus and do not auto-play under `prefers-reduced-motion`. The slider's live region is silent while it auto-plays and polite once the user takes control.
- Text contrast targets 7:1 where the CA palette allows (body on white 10.4:1, white on primary 7.6:1, muted white on navy ≥ 9:1).
- Main menu: each section is a disclosure button (`aria-expanded`/`aria-controls`) followed by its links in DOM order, so Tab moves straight from a section into its links and on to the next section (which closes the previous one). ArrowDown opens a section and moves into it, Left/Right move between sections, Esc closes and returns focus to the section button. Hover opens after a 140ms pause (80ms when switching sections) and closes 280ms after the pointer leaves, so the gap down to the menu can be crossed. Closing sections stop taking pointer events at once, so a fading section never steals a click.
- Videos: each card is one link (its title, `aria-haspopup="dialog"`). The player is a native modal `<dialog>`: focus moves to Close, Tab stays inside, Esc, Close or a click on the backdrop shut it, the video stops and focus returns to the card. The player frame has a title. After "Play video" focus stays on Close rather than inside the YouTube frame, which would otherwise swallow Esc. Without JavaScript, or in browsers without `<dialog>`, the links open the video on YouTube; Ctrl/Cmd-click still opens YouTube in a new tab.
- Videos and consent: nothing is loaded from YouTube until a video is opened, and then only from `youtube-nocookie.com`. Unless "Embedded media" is allowed in the cookie settings, the player first explains that playing loads YouTube, with a one-off "Play video" and an "Always play YouTube videos on this site" option that switches on that one setting.
- News "Read more" cues are decorative (`aria-hidden`): each story is one link (its title) whose click area covers the whole card, so screen readers hear the title once rather than a list of identical "Read more" links.
- Inner pages: a breadcrumb (`nav` + `aria-current`) and the current page marked in the header, menus and section navigation; one H1 per page.
- Forms follow the error-summary pattern: on submit, a summary at the top lists each problem as a link to its field and takes focus; the same message sits above the field, which gets `aria-invalid` and `aria-describedby`; messages clear as fields are fixed. Labels are visible, required fields use `required` plus a visible asterisk explained at the top, groups of choices are `fieldset`/`legend`, personal fields carry `autocomplete` tokens, and choices are 48px-high targets.
- Profiles open in a native modal `<dialog>` (focus moves in, Esc or the close button shuts it, focus returns to the name); without JavaScript the name is a link to the profile page.
- External links carry an icon plus visually hidden "(external site)".
- Under 380px wide the language links shrink to 36px wide so the header fits at 320px (still above the WCAG 2.2 AA 24px minimum).

## QA status (this build)

- axe-core 4.10: 0 violations at 1440, 390 and 320px (reduced motion), and with a mega-menu section, the menu overlay and the mobile menu open.
- Mega menu checked at 1100, 1440 and 1920px for hover, switching, travelling from a section button down into its links, keyboard (ArrowDown/Left/Right, Tab through and out, Esc) and click outside; without JavaScript sections open on hover and keyboard focus.
- No console errors; no horizontal scroll or clipped content at 320 / 390 / 768 / 1024 / 1100 / 1280 / 1440; works with JS disabled and with reduced motion.
- Size (esbuild minified): CSS 66.3 KB on the homepage plus 24.9 KB for inner pages (`pages.css`), JS 25.4 KB in all (modules load only when their element is on the page). The original 50 KB CSS budget was lifted by the client in v6 in favour of richer motion.
- Inner pages (48: 14 About CA, 8 Consumer Protection, 24 profiles, 2 vacancies): 0 axe violations on every page at 1440 and 390px, one H1 each, no failed requests, no console errors, no horizontal scroll. Forms (error summary, focus, messages clearing, completed state), the IMEI helper (wrong length, wrong check digit, valid), profile dialogs (open, Esc, focus return), the in-page video player and the phone section navigation were tested in Chromium; without JavaScript profile names are links and the section navigation is open.
- Lighthouse was not run in this environment.
